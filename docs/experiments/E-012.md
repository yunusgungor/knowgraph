## Experiment: E-012 — Traversal performance budget after shortest-path fix
- **Date:** 09.09.2026
- **Status:** completed
- **Theory:** E-004/E-005 added a best-depth dict, stale-skip, and shorter-path re-enqueue to the heap loop. Each pop now does a dict lookup and some nodes expand twice — worst case could inflate per-query latency on large graphs. Probe: 12-node bench graphs run ≤0.03ms/call; 100-node/400-edge graphs 0.5ms; 500-node/2000-edge graphs 2.0ms. Retrieval latency is dominated by disk I/O (read_node_json per node) and LLM synthesis (seconds), so a traversal budget of 50ms at 500n/2000e leaves 25x headroom over measured 2.0ms — if the fix ever pushes a trial over budget, the heap extras have become the bottleneck.
- **Hypothesis:** H-012: "budget_accuracy >= 0.90"

- **Experiment Design:** Bench builds the 40 E-003/E-004-shape seeded graphs (3000+t) plus one fixed 500n/2000e stress graph (seed 7); times with perf_counter (mean of 100 calls for the small graph, single call for the stress graph). Trial scores 1 iff small < 5ms AND stress < 50ms. Controlled variables: fixed seeds, no I/O in the timed section (graphs prebuilt), stdlib only. Repeatable via: python scripts/bench/bench_traversal_budget.py.
