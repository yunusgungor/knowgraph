## Experiment: E-014 — Bash-target extractor: quoted code bodies are not file paths
- **Date:** 09.09.2026
- **Status:** completed
- **Theory:** E-013 filtered glob strings and dotted imports from the -c quoted branch, but live session replay after the patch shows NEW phantoms from my own python3 -c probe commands stored in the audit log: (a) the '|' separator — the audit hook stores multi-line Bash bodies with newlines collapsed to ' | ', and the shell-op splitter turns them into pipe operators whose neighbor token '|' is emitted as a target; (b) example arguments ('a.py', 'src/gen.py', 'sys.path') quoted INSIDE -c code bodies — the open(w)/write/copy regexes and the quoted branch attribute string literals that are data, not paths. Proposed fix: when the command is an inline-code invocation (interpreter + -c/-e/-E flag), only the write-call regexes (open(w/a)/write_text/write_bytes/copy/move to a path) may yield targets; the generic quoted-string branch and the redirect/pipe-adjacent tokens inside the code body are suppressed. Real file writes via -c (open(w), write_text, copy dest) keep working because they match the write-call regexes.
- **Hypothesis:** H-014: "body_accuracy >= 0.90"
- **Measurement Metrics:** body_accuracy >= 0.90 (fraction of 40 labeled inline-code commands where the patched extractor returns exactly the expected write-target set: empty for read-only probes with example args/pipes, exact paths for real open(w)/write_text/copy writes)
- **Experiment Design:** Bench feeds 40 fixed inline-code commands (20 read-only probes incl. the exact pipe-collapsed session shapes + 20 real-write -c commands) through the patched function vendored read-only from plugin cache (same temp-package technique as E-013). Scores exact-set equality per command. Falsifiability: unpatched code fails the pipe/example-arg cases; a filter that suppresses the write-call regexes fails the write cases. Controlled variables: fixed command matrix, stdlib only. Repeatable via: python scripts/bench/bench_codebody_targets.py.
