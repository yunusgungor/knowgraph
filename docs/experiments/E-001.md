- **Date:** 09.09.2026
- **Status:** completed
- **Theory:** v1.1.0 claims deterministic retrieval: traverse_graph_reference_aware returns sorted(visited), so the same query packs the same nodes on every run. An unsorted set return would leak arbitrary iteration order into assemble_context's token-budget cut, making the same query pack different nodes each run.
- **Hypothesis:** H-001: "determinism_accuracy >= 0.90"

Controlled variables: fixed seeds (1000+t, reproducible), stdlib only, no LLM/Joern. Repeatable via: python scripts/bench/bench_traversal_determinism.py. Falsifiability: a broken implementation returning the raw unsorted set scores ~0.00 (n random UUIDs iterate in sorted order with probability ~1/n!).
